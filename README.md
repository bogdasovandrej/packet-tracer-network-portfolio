# Cisco Packet Tracer network portfolio

Три учебных проекта для начинающего сетевого инженера. Руководства написаны по-русски для Cisco Packet Tracer 9.0 и объясняют не только команды, но и ожидаемые результаты, диагностику и оформление доказательств.

| Проект | Содержание | Материалы |
|---|---|---|
| [1. Сеть благотворительного центра](project-01-charity-center/) | VLAN, trunk, router on a stick, DHCP, NAT, ACL, SSH, DNS и HTTP | `.pkt`, Word-руководство, схема, команды |
| [2. Три офиса](project-02-three-offices/) | OSPF area 0, центральный DHCP, relay, отказ и восстановление WAN | Проверенный `.pkt`, Word-руководство, схема, команды |
| [3. Пять инцидентов](project-03-incident-lab/) | Ошибки VLAN, trunk, DHCP relay, OSPF и ACL | Пять `.pkt`, Word-руководство и исправления |

## Статус воспроизведения

Все три проекта имеют файлы `.pkt`, созданные в Packet Tracer 9.0. В проекте 1 проверены адреса DHCP трёх ПК и Simple PDU: гость → внутренний сервер — `Failed`, администратор → внутренний сервер и гость → внешний сервер — `Successful` при повторной отправке после ARP. В проекте 2 проверены DHCP, соседства OSPF, ICMP и смена маршрута при отказе канала. В проекте 3 записаны пять отдельных неисправных копий: в кейсе 1 подтверждён неверный адрес гостя `10.10.20.22`, в кейсе 2 два ICMP-теста PC Volunteer → внутренний сервер завершились `Failed`, в кейсе 4 потеряно соседство OSPF, в кейсе 5 гость получил доступ к внутреннему серверу после снятия ACL. В кейсе 3 сохранено удаление DHCP relay, но симптом после принудительного обновления аренды нужно проверить самостоятельно. HTTP, DNS-имена и SSH также требуют отдельной проверки; одна успешная ICMP-проверка их не доказывает.

## Как учиться

Начать с проекта 1. После каждого этапа запустить указанную проверку, записать вывод и разобраться в причине отличия. Затем выполнить проект 2 и проверить переключение маршрута. Для проекта 3 копировать исправный baseline, вносить по одной ошибке и вести карточку расследования. Решение следует сразу после сценария, поэтому сначала сформулировать диагноз самостоятельно.

## Публикация результатов

Исходные `.pkt` уже лежат в каталогах проектов. Во время самостоятельного прохождения добавь в `evidence/` собственные снимки тестов и короткий отчёт. Не публикуй реальные пароли: `YOUR_PASSWORD` в командах проекта 1 — заглушка. Не включай в репозиторий установщик Packet Tracer или чужие учебные файлы.

## На собеседовании

Начни с задачи и схемы, затем назови свой вклад и три проверяемых факта. Для проекта 1 объясни, почему DHCP Discover нужно пропустить через гостевую ACL, хотя доступ к внутреннему VLAN запрещён. Для проекта 2 покажи `show ip ospf neighbor` и смену next hop к `10.20.1.0/24` с `10.255.12.2` на `10.255.13.2` после отключения HQ G0/1. Для проекта 3 выбери один неисправный `.pkt` и проведи расследование вслух: симптом → гипотеза → команда → причина → исправление → повторный тест. Показывай только те проверки, которые сам воспроизвёл.
