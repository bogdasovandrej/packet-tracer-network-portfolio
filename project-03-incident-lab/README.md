# Пять инцидентов

Подробные сценарии и решения — в `guide.docx`; короткие исправления — в `fixes/`. Кейсы 1, 2 и 5 требуют исправного проекта 1, кейсы 3 и 4 — исправного проекта 2. Для каждого кейса нужна отдельная копия `.pkt` с ровно одной неисправностью, исходный вывод команд, причина и проверка после ремонта.

Сейчас `.pkt` и реальные evidence не добавлены. Не называй кейсы завершёнными до их воспроизведения.

## Практическое применение и собеседование

Такой набор похож на задачи первой линии сетевой поддержки: неверная VLAN, отсутствующий VLAN в trunk, забытый DHCP relay, ошибка area OSPF и снятый ACL. На собеседовании разбери один кейс цепочкой «симптом → гипотезы → команда проверки → найденная причина → исправление → повторный тест». Не утверждай, что инциденты воспроизведены, пока не создашь и не проверишь отдельные `.pkt` для них.
