# Три офиса и OSPF

Начни с `guide.docx`. Схема и точная портовая карта приведены там же. В `configs/` — команды для R-HQ, R-B1, R-B2. Коммутаторы в этой лаборатории работают с VLAN 1 по умолчанию и специальной конфигурации не требуют.

Назови три группы устройств HQ, B1 и B2 до подключения. В разделе 3 руководства перечислены все девять кабелей: шесть соединений внутри офисов и три линии между маршрутизаторами. Сохрани учебную копию именно как `three-offices-ospf-dhcp.pkt`, чтобы имя совпало с инструкцией и репозиторием.

Файл `three-offices-ospf-dhcp.pkt` собран и сохранён в Packet Tracer 9.0. Проверено: PC-HQ — `10.20.0.21/24`, PC-B1 — `10.20.1.21/24`, PC-B2 — `10.20.2.21/24`, шлюзы `.1` своих подсетей; на R-B2 два соседа OSPF в состоянии `FULL/BDR`, маршруты к LAN HQ и B1 изучены по OSPF. Simple PDU PC-B2 → PC-B1 завершился `Successful` при повторной отправке (первый пакет ушёл на ARP). При `shutdown` R-HQ G0/1 маршрут к `10.20.1.0/24` сменил next hop `10.255.12.2` на `10.255.13.2`; интерфейс затем восстановлен командой `no shutdown` и конфигурация сохранена. Повтори тесты после открытия файла на своей версии Packet Tracer.

## Практическое применение и собеседование

Это модель сети организации с центральным офисом и двумя филиалами. OSPF автоматически пересчитывает маршруты при потере канала; центральный DHCP выдаёт адреса филиалам через `ip helper-address`. На собеседовании открой `.pkt`, покажи таблицу адресов, `show ip ospf neighbor`, `show ip route 10.20.1.0`, затем отключи HQ G0/1 и объясни, почему пакет идёт через B2. Важный акцент: разные подсети на каждом LAN, отдельные /30 для WAN и проверка реального next hop, а не только зелёных значков кабелей.
